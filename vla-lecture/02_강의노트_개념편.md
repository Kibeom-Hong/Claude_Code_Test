# Part 1. 왜 VLA인가

## 1.1 전통적인 로봇 시스템

고전적인 로봇 소프트웨어는 **모듈을 사람이 설계해서 이어 붙인 파이프라인**입니다.

```
카메라 → [인식: 물체 검출/자세 추정] → [상태 추정: 지도/위치] → [계획: 경로·잡기 계획] → [제어: 모터 토크] → 로봇
```

- 장점: 각 모듈이 해석 가능하고, 공장처럼 **환경이 고정된 곳**에서는 매우 정확하고 빠름.
- 단점:
  - **새로운 물체·새로운 환경마다 사람이 다시 설계**해야 함 (컵 대신 비닐봉지를 잡으려면? 수건을 개려면?).
  - 모듈 사이의 오류가 누적됨 (인식이 1cm 틀리면 잡기가 실패).
  - "식탁 치워줘" 같은 **애매한 언어 지시**를 이해하지 못함.

→ 그래서 **"데이터로부터 통째로(end-to-end) 배우자"** 는 흐름이 나왔고, 그 최신 형태가 VLA입니다.

## 1.2 모라벡의 역설 (Moravec's Paradox)

> "컴퓨터에게 어려운 일(체스, 수학)은 쉽고, 사람에게 쉬운 일(걷기, 물건 집기)은 어렵다."

- AI는 체스 세계 챔피언을 이겼고(1997), LLM은 시를 쓰고 코딩을 하지만,
- **빨래를 개거나 식기세척기를 비우는 로봇**은 2024년이 되어서야 데모 수준으로 등장했습니다.
- 이유: 물리 세계는 **연속적**이고, **예측이 어렵고**(천은 모양이 계속 변함), **데이터가 비싸고**, **실수 비용이 큼**(컵이 깨짐).

🎤 **말하기 포인트**: "ChatGPT는 시를 쓰는데, 왜 우리 집엔 아직 빨래 개는 로봇이 없을까요? 오늘 강의는 이 질문에 대한 답을 찾는 과정입니다."

## 1.3 LLM이 준 교훈: 파운데이션 모델

LLM이 성공한 레시피:
1. **거대한 데이터로 사전학습(pre-training)** — 인터넷 텍스트 수조 토큰
2. **목적에 맞게 사후학습(post-training / fine-tuning)** — 대화, 지시 따르기
3. 결과: **하나의 모델이 수많은 작업을 수행** (범용성, generalist)

로봇 연구자들의 질문: **"로봇에도 이 레시피가 통할까?"**
- 문제 1: 로봇 데이터는 인터넷 텍스트처럼 공짜로 쌓여 있지 않다.
- 문제 2: 로봇 출력은 단어가 아니라 **연속적인 모터 명령**이다.
- 아이디어: **이미 인터넷으로 학습된 VLM(이미지+언어 모델)을 가져와서, 로봇 행동만 추가로 가르치자!** → 이것이 VLA.

## 1.4 VLA의 정의

> **VLA (Vision-Language-Action) 모델**: 카메라 이미지(Vision)와 자연어 지시(Language)를 입력받아, 로봇이 수행할 행동(Action)을 직접 출력하는 end-to-end 모델. 보통 **사전학습된 VLM 위에** 만들어진다.

수식으로 쓰면:

$$\pi_\theta(\, a_{t:t+H} \mid I_t,\ \ell,\ q_t \,)$$

- $I_t$: 시점 t의 카메라 이미지 (1~3대: 머리/손목 카메라 등)
- $\ell$: 언어 지시 ("put the cup in the sink")
- $q_t$: 로봇의 현재 상태 (proprioception — 관절 각도, 그리퍼 열림 정도)
- $a_{t:t+H}$: 앞으로 H 스텝 동안의 행동 (H=1이면 한 스텝, H>1이면 "액션 청크")
- $\pi_\theta$: 정책(policy). 로봇 분야에서는 "관측 → 행동" 함수를 policy라고 부름.

용어 기원: **RT-2 논문(2023, Google DeepMind)** 에서 "Vision-Language-Action model" 이라는 이름을 처음 제시.

🎤 **말하기 포인트**: "VLA는 한 문장으로, '눈과 언어를 가진 AI에 손을 달아준 것'입니다. 앞으로 슬라이드에서 **청록색은 Vision, 보라색은 Language, 주황색은 Action** 입니다."

## 1.5 LLM / VLM / VLA 비교

| | LLM | VLM | VLA |
|---|---|---|---|
| 입력 | 텍스트 | 이미지 + 텍스트 | 이미지 + 텍스트 + 로봇 상태 |
| 출력 | 텍스트 | 텍스트 | **로봇 행동** (+ 때로 텍스트) |
| 예시 | GPT, Llama, Claude | LLaVA, PaliGemma, Qwen-VL | RT-2, OpenVLA, π0, GR00T |
| 틀리면? | 오답 문장 | 오답 문장 | **컵이 깨짐** (물리적 결과) |
| 데이터 | 인터넷 수조 토큰 | 이미지-텍스트 수십억 쌍 | 로봇 시연 수십만~수백만 에피소드 |

핵심 차이: VLA는 **닫힌 루프(closed-loop)** 로 동작합니다. 행동 → 세상이 바뀜 → 새 이미지 → 다음 행동. 한 번 답하고 끝나는 챗봇과 다르게 **자기 실수가 다음 입력이 되는** 구조입니다.

## 1.6 로봇의 "행동(Action)"이란?

가장 흔한 표현: **엔드 이펙터(손 끝) 기준 7차원 델타(변화량)**

| 차원 | 의미 | 예 |
|---|---|---|
| Δx, Δy, Δz | 손 끝을 얼마나 이동할지 | +1cm 앞으로 |
| Δroll, Δpitch, Δyaw | 손목을 얼마나 회전할지 | 5도 비틀기 |
| gripper | 그리퍼 열기/닫기 | 0=열림, 1=닫힘 |

다른 표현들:
- **관절 위치(joint position)**: 팔 관절 6~7개의 목표 각도. 양팔 로봇(ALOHA)은 14차원, 휴머노이드는 수십 차원.
- **절대 위치(absolute pose)** vs **델타(delta)**.
- 모바일 로봇이면 바퀴 속도(베이스 이동)도 추가.

**제어 주파수(control frequency)**: 1초에 몇 번 행동을 내보내는가.
- RT-1: 3Hz, OpenVLA: ~6Hz (RTX 4090 기준), π0: 최대 50Hz (액션 청크로), Helix/GR00T 하위 시스템: 120~200Hz.
- 빠르고 섬세한 작업(빨래 개기, 계란 집기)일수록 높은 주파수가 필요 → **"큰 모델은 느리다"는 문제**가 VLA 설계의 핵심 긴장관계.

**Embodiment(체화, 몸체)**: 로봇의 몸 형태. 팔 1개/2개, 그리퍼 종류, 바퀴 유무 등. 로봇마다 행동 공간이 달라서 **여러 로봇 데이터를 한 모델로 학습(cross-embodiment)** 하는 것이 큰 과제.

## 1.7 로봇 데이터는 어디서 오나

주로 **원격조종(teleoperation)** 으로 사람이 로봇을 직접 움직여서 모읍니다.
- **ALOHA**: 리더 팔(사람이 잡고 움직임)–팔로워 팔(따라 움직임) 구조, 저렴한 양팔 시스템
- **VR 컨트롤러 / 스페이스마우스 / 모션캡처 글러브**
- 한 에피소드 = (이미지들, 로봇 상태들, 행동들, 언어 지시)의 시계열

**데이터 격차**:
- LLM: 인터넷 텍스트 **수조~수십조 토큰**, 사실상 공짜
- 로봇: 공개 데이터 최대 규모인 Open X-Embodiment가 **약 100만 에피소드**, 사람이 한 시간씩 조종해서 모아야 함
- π0의 자체 데이터: **약 1만 시간** — 이것도 업계 최대급

→ 그래서 VLA 연구의 큰 줄기가 **"적은 로봇 데이터로 어떻게 최대한 일반화하나"** = 인터넷 지식(VLM) 활용, 여러 로봇 데이터 합치기, 시뮬레이션·사람 영상 활용.

## 1.8 Behavior Cloning(모방학습) 기초와 두 가지 함정

대부분의 VLA는 **Behavior Cloning (BC)** 으로 학습합니다: "사람 시연을 그대로 따라하도록 지도학습".

$$\mathcal{L} = \mathbb{E}_{(o, a) \sim \mathcal{D}} \big[ -\log \pi_\theta(a \mid o) \big] \quad \text{또는} \quad \| \pi_\theta(o) - a \|^2$$

쉽게 말해 **"이 장면(o)에서 사람은 이렇게(a) 움직였으니, 너도 그렇게 해"** 입니다.

### 함정 1: 누적 오차 (Compounding Error / Distribution Shift)
- 학습 데이터는 "사람이 잘 한 궤적"뿐.
- 로봇이 조금 틀리면 → 학습 때 본 적 없는 상황 → 더 틀림 → 더 낯선 상황 → ... 눈덩이처럼 오류 증가.
- 비유: 운전 연수 때 차선 중앙만 달려본 사람은, 차선에서 조금 벗어났을 때 복귀하는 법을 모름.
- 대응책: 액션 청킹, 더 다양한 데이터(실수 후 복구하는 시연 포함), 사람이 개입해 교정(DAgger류), RL.

### 함정 2: 다봉성 (Multimodality)
- 같은 장면에서 사람은 **여러 가지 정답**으로 행동함. 예: 장애물을 **왼쪽**으로 피하기도, **오른쪽**으로 피하기도.
- MSE 회귀로 학습하면 두 답의 **평균 = 정면 충돌**을 출력!
- 대응책: 분포 자체를 표현할 수 있는 출력 방식 → **이산 토큰(분류)**, **디퓨전 / 플로우 매칭(생성 모델)**.
- → 이게 바로 Part 2의 "행동 출력 방식" 논의로 이어집니다.

🎤 **말하기 포인트**: "모방학습은 두 가지 함정이 있습니다. 조금 틀리면 계속 틀리는 '누적 오차', 정답이 여러 개일 때 평균을 내버리는 '다봉성 문제'. 오늘 볼 논문들의 설계는 대부분 이 두 함정을 피하기 위한 것입니다."

# Part 2. VLA의 구성요소

## 2.1 VLA 해부도

```
 [카메라 이미지] ──▶ Vision Encoder ──▶ Projector ──┐
                     (SigLIP, DINOv2)     (MLP)      │
                                                     ▼
 [언어 지시]   ──▶ Tokenizer ─────────────────▶  LLM Backbone  ──▶  Action Head / Decoder ──▶ [행동]
                                                  (Llama, Gemma,       (토큰 디코딩 / 회귀 /
 [로봇 상태]   ──▶ (선형층 또는 토큰화) ────────▶   Qwen …)             디퓨전 / 플로우)
```

- **Vision Encoder + Projector + LLM Backbone** = 사실상 **VLM** 그대로 (LLaVA 구조와 동일)
- VLA에서 새로 생긴 부분 = **로봇 상태 입력**과 **Action Head(행동 출력부)**
- 설계 선택의 대부분은 "Action Head를 어떻게 만들까?"에 있음

## 2.2 Vision Encoder

- 이미지를 작은 **패치(patch)** 로 쪼개 각 패치를 벡터(토큰)로 바꾸는 ViT(Vision Transformer).
  - 예: 224×224 이미지, 14×14 패치 → 16×16 = **256개 토큰**
- 대표 인코더:
  - **SigLIP** (Google): 이미지-텍스트 대조학습 → "이게 뭔지"(의미)에 강함
  - **DINOv2** (Meta): 자기지도학습 → "어디에 어떤 모양"(공간·기하)에 강함
  - **OpenVLA는 둘 다 사용** (특징을 이어붙임) → 의미 + 공간 정보 모두 확보
- 여러 카메라(머리 카메라 + 손목 카메라)를 쓰면 각각 인코딩해 토큰을 이어붙임.

## 2.3 VLM Backbone — 왜 사전학습된 VLM을 쓰나

**인터넷 지식의 전이(transfer)** 때문입니다.
- 로봇 데이터에 "공룡 장난감"이 한 번도 없어도, VLM은 인터넷에서 "공룡 = 멸종된 동물"을 배웠음.
- 그래서 "멸종된 동물을 집어"라는 지시를 처음 들어도 공룡 장난감을 집을 수 있음 (RT-2의 대표 예시).
- 대표 백본: PaLI-X/PaLM-E (RT-2), Llama 2 (OpenVLA), **PaliGemma** (π0), Eagle-2/Cosmos-Reason (GR00T), Gemini (Gemini Robotics), Qwen-VL 계열 (최근 오픈소스 다수).

**주의: 파국적 망각(Catastrophic Forgetting)**
- 로봇 데이터로만 파인튜닝하면 VLM이 원래 알던 언어·상식 능력을 잊어버림.
- 해결: **Co-training** — 로봇 데이터와 인터넷 VQA/캡션 데이터를 섞어서 같이 학습 (RT-2, π0.5에서 핵심).
- 더 나아가 **Knowledge Insulation** (π0.5 계열): 행동 출력부의 그래디언트가 VLM을 망가뜨리지 않게 차단.

## 2.4 행동을 출력하는 4가지 방식 ★ (이 강의의 이론적 핵심)

LLM은 "다음 단어"를 출력합니다. 그런데 로봇 행동은 **연속적인 실수 벡터**입니다. 어떻게 할까요?

### ① 이산 토큰화 (Discretization / Binning) — RT-1, RT-2, OpenVLA
- 각 행동 차원의 범위를 **256개 구간(bin)** 으로 나눔.
- 예: Δx 범위가 [-0.05m, +0.05m]일 때, Δx = +0.013m → 약 **bin 161** → 토큰 "161"
- 7차원 행동 = **토큰 7개**. LLM이 단어 예측하듯 **분류 문제**로 학습(cross-entropy).
- 장점: VLM 구조를 **전혀 바꿀 필요 없음**. 분류라서 다봉성 표현 가능.
- 단점: 해상도 한계(256단계), 한 스텝마다 토큰 7개를 **순차 생성 → 느림**, 고주파 제어에 불리.
- OpenVLA 세부: 범위를 min/max가 아니라 **1~99 백분위수**로 잡아 이상치 영향 제거. Llama 토크나이저에서 **가장 안 쓰이는 256개 토큰을 행동 토큰으로 덮어씀**.

### ② 연속 회귀 (Continuous Regression) — OpenVLA-OFT 등
- LLM 마지막 은닉 상태 → MLP → 실수 벡터 바로 출력. L1 또는 MSE 손실.
- 장점: 빠르고 정밀, 구현 간단. 여러 스텝을 **병렬로 한 번에** 출력 가능.
- 단점: 원칙적으로 다봉성 표현 불가(평균으로 뭉개짐). 다만 시연이 일관된 데이터에서는 실제로 잘 동작함 (OFT가 LIBERO 97.1% 달성).

### ③ 생성 모델 헤드: 디퓨전 / 플로우 매칭 — Octo, π0, GR00T, RDT
- **디퓨전(Diffusion)**: 순수 노이즈에서 시작해 조금씩 노이즈를 걷어내며 행동을 "그려냄". (이미지 생성 모델 Stable Diffusion과 같은 원리, 로봇에서는 Diffusion Policy(2023)가 대표)
- **플로우 매칭(Flow Matching)**: 노이즈 → 정답 행동으로 가는 **"속도(방향) 벡터"** 를 학습. 디퓨전보다 더 곧은 경로라 **적은 스텝(예: 10번)으로 생성** 가능.
- 장점: **다봉성을 자연스럽게 표현**(왼쪽/오른쪽 중 하나를 샘플), 연속·고정밀, 액션 청크를 통째로 생성.
- 단점: 여러 번 반복 계산 필요(그래도 flow는 10스텝 정도), 구현이 조금 복잡.

**플로우 매칭 직관 (π0에서 사용)**:
1. 정답 행동 청크 $A$ 와 노이즈 $\epsilon \sim \mathcal{N}(0, I)$ 를 준비
2. 무작위 시간 $\tau \in [0,1]$ 을 뽑아 둘을 섞음: $A^\tau = \tau A + (1-\tau)\epsilon$
3. 모델에게 "이 섞인 점에서 정답 쪽으로 가려면 어느 방향?"을 맞추게 함. 정답 방향은 $A - \epsilon$ (π0 논문·openpi 코드는 시간 방향을 반대로 잡아 $u = \epsilon - A$ 로 표기하지만 본질은 같음 — 질문 나오면 "부호 관례 차이"라고 답하면 됨)
   $$\mathcal{L} = \mathbb{E}\, \big\| v_\theta(A^\tau, o) - (A - \epsilon) \big\|^2$$
4. 추론 시: 노이즈에서 시작해 예측된 속도 방향으로 10번 조금씩 이동(오일러 적분) → 행동 청크 완성

🎤 비유: "안개 속(노이즈)에서 목적지(정답 행동)를 향해 나침반(속도 벡터)을 보며 10걸음 걷는 것."

### ④ 압축 토큰화 (FAST) — π0-FAST, π0.5 사전학습
- ①의 단순 binning은 고주파(50Hz) 데이터에서 **연속된 토큰이 거의 같은 값** → 모델이 "이전 토큰 복사"만 배우는 문제.
- FAST는 행동 시퀀스를 **DCT(이산 코사인 변환, JPEG에 쓰이는 것)** 로 주파수 영역으로 바꾸고, 양자화 후 **BPE로 압축** → 적은 수의, 정보가 꽉 찬 토큰.
- 결과: 자기회귀(토큰) 방식으로도 디퓨전 수준의 성능, **학습 속도 약 5배** 빠름 (단, 추론은 토큰을 순차 생성하므로 플로우보다 느림).
- 자세한 설명은 2.6절.

### 한눈에 비교

| 방식 | 대표 모델 | 다봉성 | 정밀도 | 추론 속도 | VLM 구조 변경 |
|---|---|---|---|---|---|
| ① 이산 토큰(binning) | RT-2, OpenVLA | ○ | △ (256단계) | 느림 (순차) | 없음 |
| ② 연속 회귀 | OpenVLA-OFT | ✕ | ○ | 매우 빠름 (병렬) | 헤드 추가 |
| ③ 디퓨전/플로우 | Octo, π0, GR00T | ◎ | ◎ | 중간 (반복 10스텝~) | 액션 전문가 추가 |
| ④ 압축 토큰(FAST) | π0-FAST | ○ | ○ | 느림 (순차) | 토크나이저만 |

🎤 **말하기 포인트**: "VLA 논문을 읽을 때 가장 먼저 볼 것은 '행동을 어떻게 출력했나'입니다. 토큰으로? 숫자로 바로? 아니면 그림 그리듯 생성으로? 이 선택이 속도, 정밀도, 학습 효율을 다 결정합니다."

## 2.5 액션 청킹 (Action Chunking)

- 한 번에 1스텝이 아니라 **미래 H스텝(예: 50스텝 = 1초)** 을 한꺼번에 예측.
- 출처: ACT/ALOHA (Zhao et al., 2023), Diffusion Policy (Chi et al., 2023)에서 대중화 → π0, GR00T 등 대부분 채택.
- 왜 좋은가?
  1. **누적 오차 감소**: 결정 횟수가 1/H로 줄어듦 → 오류 누적 기회 감소.
  2. **시간적 일관성**: 사람 시연에는 "잠깐 멈춤" 같은 비마르코프적 행동이 있는데, 청크는 이를 자연스럽게 표현.
  3. **속도**: 무거운 모델을 1초에 1~2번만 돌려도 50Hz 제어 가능.
- 실행 방식:
  - 청크를 **일부만 실행하고 다시 예측**(receding horizon, 예: 50개 중 25개 실행)
  - **Temporal ensembling**(ACT): 겹치는 예측들을 가중 평균
  - **Real-Time Chunking / 비동기 추론**: 현재 청크 실행 중에 다음 청크를 미리 계산 (π0 계열, SmolVLA 등)

🎤 비유: "운전하면서 매 순간 핸들을 새로 결정하는 게 아니라, '앞으로 1초 동안은 이렇게 꺾자'고 계획하는 것."

## 2.6 FAST: 행동을 JPEG처럼 압축하기

(Pertsch et al., 2025, Physical Intelligence) — Frequency-space Action Sequence Tokenization

**문제**: 50Hz로 행동을 단순 binning하면 1초 청크 = 50스텝 × 14차원 = **700토큰**. 게다가 이웃 토큰끼리 거의 같은 값이라 토큰 하나당 정보량이 매우 작음 → 모델이 "그냥 이전 값 복사"를 배워버리고 학습이 잘 안 됨.

**해법 (4단계)**:
1. **정규화**: 각 차원을 [-1, 1]로 (1~99 백분위수 기준)
2. **DCT**: 각 차원의 시계열을 주파수 성분으로 변환. 부드러운 동작은 **저주파 계수 몇 개**에 에너지가 몰림 (JPEG가 사진을 압축하는 원리와 같음)
3. **양자화**: 계수에 스케일을 곱하고 반올림 → 대부분의 고주파 계수가 **0**이 됨
4. **BPE 압축**: 저주파부터 차원별로 인터리브해 나열 → 0이 많은 시퀀스를 BPE(LLM 토크나이저 방식)로 압축 → **약 30~60개 토큰**

**결과**: π0-FAST는 디퓨전 기반 π0과 비슷한 성능, **학습 시간은 약 5배 단축**. FAST+ 라는 범용 토크나이저(100만 개 궤적으로 학습)도 공개.

### 학습 레시피 (LLM과 평행)
1. **VLM 사전학습** (이미 되어 있는 것을 가져옴): 인터넷 이미지-텍스트
2. **로봇 사전학습(pre-training)**: 여러 로봇·여러 작업의 대규모 데이터 → 범용 "기초 체력"
3. **사후학습(post-training / fine-tuning)**: 목표 로봇·목표 작업의 고품질 데이터 → 특정 기술 숙련
4. (최근) **강화학습(RL) / 경험 학습**: 로봇이 직접 해보고 성공/실패로 개선 (π*0.6 RECAP 등)

**Co-training**: 2~3단계에서 인터넷 VQA/캡션 데이터를 섞어 언어·상식 능력 유지 + 로봇 데이터로 행동 학습.

**Cross-embodiment**: 로봇마다 행동 차원이 다름 → 가장 큰 차원으로 **zero-padding** 해서 통일(π0), 또는 **로봇별 입출력 층**을 두고 몸통은 공유(Octo, GR00T, HPT).

## 2.8 두 가지 아키텍처 계열: 단일 시스템 vs 이중 시스템

| | 단일 시스템 (Monolithic) | 이중 시스템 (Dual-System, Hierarchical) |
|---|---|---|
| 구조 | 하나의 모델이 인식→행동 | **System 2**(느린 VLM, 생각) + **System 1**(빠른 정책, 반사) |
| 예시 | RT-2, OpenVLA, π0 | Figure **Helix**(7~9Hz + 200Hz), NVIDIA **GR00T N1**(10Hz + 120Hz), Gemini Robotics(클라우드 백본 + 로컬 디코더) |
| 장점 | 단순, end-to-end 학습 | 큰 모델의 지능 + 빠른 제어를 동시에 |
| 단점 | 큰 모델이면 느림 | 두 시스템 사이 인터페이스 설계가 어려움 |

이름의 기원: 대니얼 카너먼의 『생각에 관한 생각(Thinking, Fast and Slow)』 — 빠르고 직관적인 System 1, 느리고 숙고하는 System 2.

π0/π0.5는 중간 형태: 하나의 모델 안에 **VLM(큰 두뇌) + Action Expert(작은 행동 전문가)** 를 두고 어텐션으로 연결. π0.5는 여기에 "먼저 텍스트로 하위 작업을 말하고 → 그 다음 행동"하는 **계층적 추론**까지 한 모델에서 수행.

# 부록. 용어 사전

| 용어 | 쉬운 설명 |
|---|---|
| Policy (정책) | 관측을 받아 행동을 내놓는 함수. 로봇의 "두뇌" |
| End-effector | 로봇 팔 끝의 손(그리퍼) |
| Proprioception | 로봇이 자기 몸 상태를 아는 감각 (관절 각도 등) |
| DoF (자유도) | 독립적으로 움직일 수 있는 축의 수 |
| Teleoperation | 사람이 원격으로 로봇을 조종해 데이터를 모으는 것 |
| Episode / Trajectory | 한 번의 작업 시도 전체 기록 |
| Behavior Cloning (BC) | 시연을 지도학습으로 따라하는 모방학습 |
| Embodiment | 로봇의 몸 형태 (팔 수, 그리퍼 등) |
| Cross-embodiment | 서로 다른 몸의 로봇 데이터를 함께 학습 |
| Action chunk | 한 번에 예측하는 미래 여러 스텝의 행동 묶음 |
| Co-training | 로봇 데이터와 인터넷 데이터를 섞어 함께 학습 |
| Flow matching | 노이즈→데이터로 가는 속도장을 학습하는 생성 모델 방식 |
| Zero-shot | 추가 학습 없이 바로 수행 |
| Emergent capability | 명시적으로 가르치지 않았는데 나타나는 능력 |
| Sim-to-real | 시뮬레이션에서 학습해 실제 로봇에 적용 |
| Closed-loop | 행동 결과를 다시 관측해 다음 행동에 반영하는 방식 |
